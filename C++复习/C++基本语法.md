# C++面向对象三大特性
## 1.封装

封装： 把（数据）和（操作）打包在类里，通过（public/private/protected）控制访问权限，外部只能通过（接口）操作，不能直接改（数据）；
核心思想是：“隐藏实现细节，只暴露接口”。private成员外部不可访问，protected成员子类可以访问，public成员所有人都可访问，好处是提高安全性，修改内部实现不影响外部调用

## 2.继承
继承：子类复用父类的属性和方法，在原有功能基础上扩展，避免重复代码；
子类自动拥有父类的非私有成员，可以重写override父类方法来改变行为。比如Animal基类，派生出Dog、Cat，共享name属性但各自实现不同的speak方法
继承有三种方式：public（最常用，保持父类接口），protected、private区别在于父类成员在子类中的访问级别变化；

通用规则：无论采用哪种继承方式，派生类都永远不能直接访问基类的 private（私有）成员，但这些私有成员依然存在于派生类对象的内存中。

**构造顺序**：先构造父类 → 再构造成员对象 → 最后构造子类自身。派生类的构造函数通常需要通过初始化列表显式调用父类的带参构造函数。
**析构顺序**：与构造顺序完全相反。先析构子类自身 → 再析构成员对象 → 最后析构父类。

需要注意的是，析构函数不能被继承，必须在派生类中自行定义（特别是涉及动态内存分配时，以防内存泄漏）；如果是基类指针来new子类对象，那么基类必须虚析构，子类重写析构。如果是子类指针new子类对象，则不需要虚析构

**重写**：父子关系，参数同，运行定，换实现。
**重载**：同类关系，参数异，编译定，多版本。

如果父类函数不加virtual，子类写了同名同参的函数，不是重写，是隐藏。通过父类指针调用时永远调父类版本，多态失效
重写返回值有一种例外可以不一样，父类返回Base*，子类返回Derived*
## 3.多态

多态：同一个接口，不同（对象）调用表现不同。分（编译）时多态（函数重载、模板）和（运行）时多态（虚函数 + 继承）

**编译时多态（静态绑定）**：函数重载，运算符重载，overload，模板；在编译阶段就确定调用哪个函数；  没有运行时开销。
**重载条件**：
1. **同一作用域**：函数必须在同一个命名空间、同一个类或同一个全局作用域中；
2. **函数名称相同，参数列表不同**：三个维度（参数个数不同，参数类型不同，参数顺序不同）和返回值没有关系。

**运行时多态（动态绑定）**：通过虚函数实现。基类指针/引用指向派生类对象时，调用的时派生类的重写版本，而不是基类版本。
**运行时多态满足三个条件**：1.存在继承关系；2.虚函数和重写override（函数名、参数列表、返回值类型必须完全一致）；3.基类的指针或引用

**运行时多态的底层机制**：
1. 每个含虚函数的类，编译器生成一张vtable虚函数表（静态的指针数组），顺序存放该类所有虚函数的地址；
2. 每个对象内部（内存布局首部）有一个隐藏的vptr（虚表指针），指向所属类的vtable
3. 通过基类指针调用虚函数时，程序顺着vptr找到vtable，再通过间接寻址从表里取出实际函数地址调用
vtable 是类级别的（同类所有对象共享一张表），vptr 是对象级别的（每个对象各有一个（多继承有多个））

**动态绑定过程**：
	当你通过基类指针调用虚函数时，程序会先解引用对象的 vptr 找到 vtable，再根据虚函数在表中的偏移量，索引到正确的派生类函数地址，最终完成间接跳转

**子类虚函数表的生成**：
1. 复制基类虚表：编译器在编译子类时，会先复制一份基类的虚函数表作为子类的初始虚表。
2. 覆盖重写项：编译器会检查子类中重写了哪些虚函数。如果重写了，就在新生成的虚表中，将对应槽位（slot）的指针替换为子类重写函数的地址。
3. 追加新虚函数：如果子类自己又定义了新的虚函数，编译器会在虚表的末尾追加新的槽位，存放新虚函数的地址。
4. 如果子类是多继承（例如 class C : public A, public B，且 A 和 B 都有虚函数），那么子类对象内部会有多个 vptr（分别指向继承自 A 和 B 的虚表），同时编译器还会为 C 生成一个属于自己的、合并后的主虚表。

# 指针和引用

## 1.指针

指针是存储地址的独立变量，可重新赋值、可为空、支持算术运算，但需要手动管理内存。既然是变量，它自己本身也占据内存空间，指针支持多级间接int**，访问目标时需要解引用，sizeof返回指针本身大小。
const 修饰指针：
	const int* p和int const* p是常量指针，指向常量的指针，指向可以改，指向的内容不能改；常用于函数传参；告诉调用者：“我只读这个数据，绝不修改它”，既安全又避免了拷贝开销。
	int* const p是指针常量，指向不能改，指向的内容可以改；常用于类的成员变量，比如某个对象内部持有一个绝对不能被替换的底层资源句柄。

悬空指针：1.返回局部变量的引用（最经典）；2.容器扩容导致引用失效，比如vector插入元素触发了内存重新分配，所有指向该容器的指针和引用都会失效

## 2.引用

引用是变量的别名，必须初始化、不能为空、绑定后不可更改，编译器不为其分配独立存储空间。它不是一个独立的变量，不支持算术运算，必须在声明的时候初始化，sizeof返回绑定对象的大小

底层实现：在底层汇编级别，编译器通常是将引用实现为一个指针常量（const pointer）。
	int& r = a; 在底层可能等价于 int* const r = &a;
区别在于：指针的语法允许你解引用（* p）和取地址（&p），而引用在语法层面屏蔽了这些操作，让你感觉不到指针的存在，从而提高了代码的安全性。

## 3.指针和引用适用场景

用指针：需要改变指向或指针算术运算如遍历链表等；需要表达可能为空；
用引用：函数传参，函数返回值

# 结构体和类

C++中struct和class在语法能力上完全等价，区别只有两个默认行为：
1. 默认成员访问权限不同。 struct 的成员默认 public，外部可以直接访问；class 的成员默认 private，必须通过公开接口访问。但两者都可以显式写 public/protected/private，所以这只是默认值的差异，不是能力的差异。
2. 默认继承权限不同。 struct Derived : Base 默认是 public 继承，class Derived : Base 默认是 private 继承。private 继承会导致基类的 public 成员在派生类外部不可访问。实际写代码时都会显式写继承权限，不依赖默认行为。
3. 模板参数声明。 template < class T >  或 template< typename T> 都合法，但不能写 template< struct T > 。这是语法规定，和 struct/class 的语义无关。

工程惯例上，struct用于纯数据聚合，典型场景：配置项、坐标点、网络协议包头、POD 类型。class用于有封装行为的类型。

## 结构体和联合体区别

1. struct的所有成员各自占用独立内存，sizeof是所有成员的大小之和（存在内存对齐）
2. union的所有成员共享同一块内存，sizeof等于最大成员的大小，同一时刻只有一个成员有效，union不支持继承，不能有虚函数和引用成员，永远是pbulic
3. union的所有成员从同一个起始地址开始，共享了同一块内存，一个union{int a;double b; char c}只占8个字节。写入一个成员会覆盖其他成员的值。读取一个未被最近赋值的成员会导致未定义行为。
4. 现代C++17中使用std::variant来替代union；完美解决了原生 union 容易引发未定义行为，可以把它理解为一个“知道自己当前存了什么类型”的超级联合体
5. union经典场景是二进制协议解析，把一块儿buffer按不同字段解释，同时还节省内存

# static和const关键字

## 1.static
static控制的是“在哪儿活多久”：让局部变量在函数调用之间持久存在，让全局符号限制在当前文件可见，让类成员可以被所有对象共享；
### 1.1局部静态变量
生命周期会被延长到程序结束，但是作用域还是在函数体内。只需要初始化一次，后续调用保留上次的值；（存储在全局数据区，而不是栈区。）生命周期的改变根本原因是存储位置发生变化.data或.bss

### 1.2文件作用域的static 全局变量
限制符号为内部链接，其他的.cpp文件无法通过extern访问，实现了文件级私有；
静态全局变量与静态函数，改变了变量的链接属性，被 static 修饰的全局变量或函数，仅在当前编译单元（当前 .cpp 文件）中可见，属于内部链接（Internal Linkage），即使其他文件中存在同名的全局变量或函数，也不会发生链接冲突。这非常适合用来隐藏模块的实现细节。

### 1.3类的静态成员变量
属于类本身而非某个对象，所有对象共享一份，在类内部只是声明，必须在类外部进行定义和初始化；

### 1.4类的静态成员函数
没有this指针，不能访问非静态成员，可通过类名::函数名直接调用；

静态成员变量需要注意线程安全，因为它在内存中只有一份，却被所有线程共享，多线程下所有线程访问的是同一个地址。如何避免：使用static std::atomic。

### 1.5 extern
extern核心作用是声明外部链接（External Linkage），告诉编译器变量的名字和类型，不分配内存。extern 通常用于声明，告诉编译器：“这个变量或函数在别的地方（比如另一个 .cpp 文件）已经定义了，你只管用，链接器会去找它。

**场景1：**
// --- file_a.cpp ---
int g_score = 100;  // 定义全局变量（默认就是外部链接）
// --- file_b.cpp ---
extern int g_score; // 声明变量在外部定义
如果说 static 是“把东西藏起来，只给自己用”，那么 extern 就是“把东西拿出来，给大家用”。

场景2：
C++ 调用 C 语言代码（extern "C"）
C++ 支持函数重载，因此编译器会对函数名进行“名称修饰（Name Mangling）”。而 C 语言不支持重载，不会进行名称修饰。
当 C++ 代码需要调用 C 语言编写的库时，必须使用 extern "C" 告诉 C++ 编译器：“不要用 C++ 的方式去修饰这个名字，按 C 的方式去找”。

```
写 C/C++ 通用头文件时，用 
#ifdef __cplusplus 包裹 extern "C"，这样同一个头文件既能被 C 编译器用，也能被 C++ 编译器用。
C 编译器看不到 extern "C"（因为 __cplusplus 未定义），C++ 编译器能看到并正确处理
```

## 2.const

const控制的是“能不能改”：把变量标记为只读，把指针/引用标记位不可通过它修改所指对象，把成员函数标记位不会修改对象状态（成员变量）
### 2.1 修饰普通变量
和普通变量一样存储在栈上，修饰全局变量时，存储在只读数据段rodata

### 2.2 修饰指针
常量指针 (const int* 和int const* )：指针的指向可以改，指向的内容不能改；指针常量（int* const）

### 2.3 修饰引用
const int&ref = x,表示不能通过ref修改x，常用于函数传参

### 2.4 修饰成员函数
承诺不修改对象的任何非mutable成员，const对象只能调用const成员函数


**const 和 constexpr的区别**：const是运行时只读，初始值可以运行时才确定。constexpr更强，是编译期常量




构造函数：
C++的构造函数主要有六种：默认构造、参数化构造、拷贝构造、移动构造、委托构造、继承构造
核心的区别是出发诗句和资源处理方式不同：默认构造负责零初始化，拷贝构造复制资源，移动构造转移资源所有权，委托构造复用初始化逻辑，继承构造透传基类初始化。
构造函数不能是虚函数，虚函数机制依赖于已构造的虚表指针，而构造期间vptr尚未就绪

1.默认构造，未定义构造函数时自动生成，如果定义了其他构造函数后需要=default显示声明，没有参数；

2.参数化构造，不会自动生成，用户自定义，带参创建对象；

3.拷贝构造函数，className(const ClassName&)，未定义时自动生成（浅拷贝）。使用已有对象初始化新对象（可分为深拷贝和浅拷贝）；
核心作用实现对象复制，并防止浅拷贝导致的内存错误，参数必须是同类对象的引用（通常使用const修饰）。

| ClassName(const ClassName& other);              | 最常见形式        |
| ----------------------------------------------- | ------------ |
| **ClassName(ClassName& other);**                | **非const版本** |
| **ClassName(volatile ClassName& other);**       |              |
| **ClassName(const volatile ClassName& other);** |              |
参数必须是引用，不能值传递，否则会无限递归调用导致栈溢出。因为自定义类型按值传参时，编译器必须调用该类型的拷贝构造来创建形参副本。

如果类中包含指针成员并动态分配了堆内存，默认的浅拷贝会导致两个对象的指针指向同一块内存，析构的时候会重复释放，导致程序崩溃，此时必须自定义拷贝构造函数。

3.1深浅拷贝的区别
浅拷贝：只复制对象的成员变量值。对于指针成员，复制的是地址本身，两个对象的指针指向同一块内存；
浅拷贝的问题：双重释放、一个对象析构后，另一个对象的指针指向已被释放的内存，访问了悬垂指针、意外修改，一个对象修改数据，另一个对象的也改了。
深拷贝：为指针成员重新分配内存并复制内容，两个对象各自拥有独立的堆内存，互不影响；

---

4.移动构造，className(ClassName&&)，未定义拷贝/移动操作且未定义析构时自动生成，窃取临时对象资源，避免深拷贝；
4.1参数必须是右值引用：只能绑定临时对象（纯右值）或被std::move转换后的对象（将亡值）；
4.2必须标记noexcept：如果移动可能抛异常，std::vecotr等标准容器扩容时会回退到拷贝构造，导致优化失效；
4.3必须将源对象资源指针置空：防止析构时重复释放同一块内存；
4.4隐式生成规则：如果类自定义了析构函数、拷贝构造或拷贝赋值中的任意一个，编译器不会自动生成移动构造。

5.委托构造：不会自动生成，一个构造函数在初始化列表中调用同类其他构造函数，避免重复代码；
5.1委托构造必须在初始化列表中进行，不能在函数体中调用；
5.2一旦使用了委托构造，初始化列表中不能再初始化其他成员；
5.3执行顺序：先完整执行被委托构造函数的初始化列表和函数体，再返回执行委托者的函数体；
5.4委托链可以是多级的，但不能形成环

6.继承构造：不会自动生成，需using声明，派生类直接使用基类构造函数，using Base::Base;
6.1拷贝和移动构造不会被继承


虚函数
1.虚函数和纯虚函数区别
虚函数用virtual声明，有默认实现，派生类可以选择性重写，类可以实例化
一般用来提供默认行为，允许定制
纯虚函数需virtual且声明后加=0，没有默认实现，派生类必须重写，类不能实例化（抽象类）
定义接口规范，每个派生类行为都不同
纯虚函数可以在类外给纯虚函数写实现体，派生类可以通过Base::fun()显示调用。

多重继承
多重继承可以让一个类同时继承多个基类，好处是能组合多个接口，复用多个类的功能。坏处是多个基类有同名成员时产生二义性。
菱形继承问题：最顶层基类数据存了多份，浪费内存空间；通过子类访问最顶层基类成员时，编译器不知道该用B路径还是C路径的顶层基类数据，必须用d.B::name或d.C::name
![[Pasted image 20260914155403.png]]
虚继承解决此问题，B和C用virtual public A继承时，编译器不再把A的子对象直接嵌入B和C内部，而是在B和C里各放一个虚基类指针（VBptr），指向虚基类表（VBTable），表里记录了A子对象相对于当前对象的偏移量。最终D的内存不距离只有一份A，B和C通过各自的vbptr间接访问这份共享的A。代价是多了一次间接寻址

如何禁止类被继承：
final修饰，class MyClass final。在C++11前需要用私有构造函数+虚继承+友元来替代
常见场景：工具类（只有静态方法，没有状态）、性能关键类

this指针
this指针本质是指针常量，指向不能变，指向的对象可以变，在const成员函数中，this变为const T* const，指向和指向对象都不能变
如果需要在对象内部获取指向自身的shared_ptr，不能直接shared_ptr<T>(this)，必须继承std::enable_shared_from_this<T>，然后调用shared_from_this();

单例模式
确保类只有一个实例，提供全局访问点。
核心手段是：构造函数私有化+删除拷贝/赋值+静态方法返回唯一实例
1.饿汉模式：程序启动时就创建实例。天然线程安全，但如果单例很重且可能用不到，就浪费资源。多个饿汉式单例直接的初始化顺序不确定
```
class Singleton
{
private:
		Singleton(){}
		 static Singleton instance;//静态实例
public:
		 static Singleton& getInstance()
			 {
				 return instance;
			 }
};
//在main()之前初始化
Singleton Singleton::instance;
```

3.双检锁：在懒汉模式基础上加锁。第一次检查避免每次都加锁，加锁后第二次检查避免重复创建
```
class Singleton
{
privtae:
	static std::mutex mtx;
	 static std::atomic<Singleton*> instance;
	 Singleton(){}
public:
		static Singleton* getInstance()
		 {
		 Singleton* tmp = instance.load(std::memory_order_acquire);//使用内存序
			 if（tmp == nullptr)//第一次检查，避免每次都加锁
			 {
				 std::lock_guard<std::mutex>lk(mtx);//加锁
				 tmp = instance.load(std::memory_order_relaxed);
				 if(tmp == nullptr)//第二次检查，确保至于偶一个线程创建
				 {
					 tmp = new Singleton();
					 // 赋值：使用 memory_order_release
					 // 确保 new 操作（包括构造函数）在赋值给 instance 之前全部完成
					 instance.store(tmp, std::memory_order_release);
				 }
			 }
			 return instance;
		 }
};
Singleton* Singleton::instance = nullptr;
std::mutex SIngleton::mtx;
```
第一次检查：如果instance已经不为空，说明已经创建过了，直接返回即可，不需要加锁；
第二次检查原因：线程A检查instance == nullptr，结果为真，准备进入锁区域，此时线程A被操作系统挂起（时间片用完），线程B进来检查instance == nullptr也为真，进入锁区域，创建实例，释放锁，线程A此时恢复运行，由于之前已经通过第一次检查，于是再次进入锁区域，又会创建一个新实例，覆盖了线程B创建的实例（或会导致内存泄漏）。因此需要在进入锁后再次检查是否为空

PS：这种场景在C++11之前还是不安全的，原因是 instance = new Singleton();操作编译器底层会分三个步骤；1.分配内存；2.调用构造函数；3.赋值指针。为了提高执行效率，可能会进行指令重排序，2和3步骤发生交换。为了防止重排序，使用atomic和内存序解决解决

4.Magic Static：函数内的局部static变量，C++11标准规定其初始化必须是线程安全的。代码只需一行，没有手动锁没有指针、没有内存泄漏。
```
class Singleton
{
	private:
			Singleton(){}
			 Singleton(const Singleton&) = delete;
			 Singleton& operator=(const Singletonm&) = delete;
	 public:
		 static Singleton& getInstance()
		 {
			 static Singleton instance；//C++11保证局部静态变量初始化线程安全
			 return instance;
		 }
}
```
C++11标准明确规定，局部静态变量的初始化过程是线程安全的。如果多个线程首次调用该函数，初始化操作会被正确序列化，只有一个线程会执行初始化，其他线程会等待。
对于生命周期的管理，由于是静态局部变量，生命周期是整个程序运行期间。

单例模式缺点：
1.由于是全局状态，会导致单元测试困难，全局状态难隔离
2.违反单一职责，既管业务又管自己生命周期
3.适用场景：日志，配置管理
